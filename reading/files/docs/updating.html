Updating findings and publishing new versions

Published snapshots retain their exact files, evidence cutoff and checksums. A public availability date records the actual publication event, separately from experiment and preparation dates.

• Preserve each new experiment's original data, identity, configuration and complete outcome.

• Distinguish measured, source-verified, derived and unresolved claims. Keep unsuccessful outcomes in the evidence record.

• Review privacy and redistribution rights before exporting derivatives. Exclude private paths, credentials and raw ambient transmissions.

• Update the run and claim registries, report, appendix, overview and affected documentation together.

• Run the offline checks, regenerate figures/PDF/site and inspect all rendered pages. Bind the exact export in the file and licence manifests.

• Review the exact package before publication. Publish a new version rather than replacing an earlier report or changing its historical evidence.

Use a patch version for corrections within the same evidence scope; use a minor version for substantial new findings or capabilities. Version 0.3.0 is the initial publication package, consolidating the prior local research reviews. This numbering does not imply production readiness.

The report presents accepted results and general limitations. Original unsuccessful outcomes remain in the registries. Keep the explanation of the existing collector, inspiration from ESP-SDR and this specific implementation consistent across materials. No presentation edit can extend a measurement's scope.
